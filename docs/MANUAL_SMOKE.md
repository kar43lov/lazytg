# Manual Smoke Checklist (Stages 2 + 3)

Этот чек-лист дополняет автоматизированные unit/integration/e2e тесты в `internal/...` и `test/...` ручной проверкой UX-аспектов TUI, которые невозможно адекватно покрыть headless-тестами (визуальный рендер, latency восприятия, поведение в реальном терминале).

Прогон обязателен перед мерджем Stage 2 в `main` и перед каждым `v0.1.0-alpha.N` релизом.

## Подготовка

1. Соберите бинарь из ветки Stage 2:
   ```sh
   make build
   ./bin/lazytg version  # подтвердить, что собралось
   ```
2. Убедитесь, что есть хотя бы один залогиненный аккаунт (тестовый, не основной — см. ban-risk warning в `CLAUDE.md`):
   ```sh
   LAZYTG_API_ID=... LAZYTG_API_HASH=... ./bin/lazytg login --account +<phone>
   ./bin/lazytg accounts  # должен показать аккаунт со звёздочкой
   ```
3. Откройте лог-файл в отдельном tmux-pane для наблюдения:
   ```sh
   tail -F ~/.local/state/lazytg/lazytg.log  # Linux
   tail -F ~/Library/Application\ Support/lazytg/lazytg.log  # macOS
   ```

## Чек-лист

### 1. Запуск TUI без подкоманды

- [ ] `./bin/lazytg` (без аргументов) — открывается 2-pane TUI
- [ ] В левой панели появляется список чатов (если кешированные данные есть в SQLite — сразу; если нет — пусто, но без crash)
- [ ] Status-bar в нижней строке показывает `<phone> | - | unread 0 | connecting | rw` (или `online` если уже подключились)
- [ ] Терминал в alt-screen режиме (после выхода — терминал восстанавливается, scrollback не загажен)

### 2. Терминал слишком маленький

- [ ] Уменьшите окно терминала до 60×20 (или меньше) → появляется отцентрованное сообщение `Terminal too small (min 80x24)`
- [ ] Увеличите обратно — нормальный layout восстанавливается без перезапуска

### 3. Навигация и фокус

- [ ] `Tab` — фокус циклит `Chats → Input → Thread → Chats`
- [ ] `Shift+Tab` — фокус циклит в обратном направлении
- [ ] Активный pane выделен ярким синим (ANSI 12) на рамке
- [ ] Заголовок Chats pane меняется на `Chats (focused)` при фокусе

### 4. Список чатов

- [ ] Стрелки `↑/↓` или `j/k` (когда фокус на Chats pane) перемещают выделение
- [ ] Pinned чаты (📌) идут первыми
- [ ] Unread-счётчик отображается в скобках после названия (когда > 0)
- [ ] `/` запускает встроенный фильтр bubbles/list (опционально, не критично)

### 5. Открытие чата

- [ ] `Enter` на выбранном чате — справа загружается история сообщений
- [ ] Title чата появляется в status-bar
- [ ] Сообщения отображаются oldest-first (сверху вниз)
- [ ] Viewport начинает с самого свежего сообщения (snap to bottom)

### 6. Pagination

- [ ] Прокрутите Thread pane вверх (`PgUp` или `Ctrl+B`) до самого верха
- [ ] При наличии большего количества истории — догружается следующая страница (200 сообщений)
- [ ] Ваша позиция чтения остаётся стабильной после догрузки (не "прыгает" вниз)

### 7. Ввод и отправка сообщения

- [ ] `Tab` → фокус Input
- [ ] Печатаете текст — отображается в textarea с курсором `›`
- [ ] `Enter` — сообщение уходит, появляется в треде с префиксом `[⏳]` (optimistic, pending)
- [ ] Через ≤500ms префикс пропадает — message confirmed (state=sent)
- [ ] Telegram-клиент на телефоне получает то же самое сообщение
- [ ] textarea очищается после отправки

### 8. Multi-line newline

- [ ] `Alt+Enter` в Input pane — добавляется literal `\n`, можно набирать многострочный текст
- [ ] `Enter` (без Alt) на многострочном тексте — отправляет всё как одно сообщение

### 9. Reply

- [ ] Фокус Thread → выберите сообщение (если поддерживается выделение в треде, иначе reply на последнее)
- [ ] `Ctrl+R` — в Input pane появляется reply-hint `↳ Reply to: <preview>`
- [ ] Печатаете ответ → `Enter` → сообщение уходит как reply (на телефоне видно как replied-to)
- [ ] Reply-pointer сбрасывается после отправки

### 10. $EDITOR delegation

- [ ] `EDITOR=vi ./bin/lazytg` — запускаете
- [ ] В Input `Ctrl+E` → `vi` открывается с текущим содержимым textarea
- [ ] Сохраняете (`:wq`) → возвращаетесь в TUI, textarea содержит отредактированный текст
- [ ] Повторите с `EDITOR=nano` — то же поведение
- [ ] Повторите с `EDITOR=cat` — текст из textarea выводится, после `Ctrl+D` возврат в TUI

### 11. Help overlay

- [ ] `?` (когда не в textarea и не во время фильтрации) — открывается modal с табличкой `Action | Binding`
- [ ] Все hotkeys из default keymap присутствуют (send, newline, reply, open editor, focus next/prev, scroll up/down, quit)
- [ ] `Esc` или `q` или повторное `?` — закрывает overlay
- [ ] Пока overlay открыт — другие keys (`Tab`, печатные символы) игнорируются

### 12. Live updates

- [ ] Откройте чат с человеком, который активен в Telegram
- [ ] Попросите написать сообщение / отправьте себе с другого устройства
- [ ] Сообщение появляется в Thread pane без обновления, ≤500ms latency
- [ ] Если вы были scrolled-up — позиция чтения не меняется (sticky scroll работает)
- [ ] Если вы были на bottom — viewport скроллится к новому сообщению

### 12a. Отметки о прочтении, удаления и новые чаты

Четыре пути, которых не существовало до 19.08.2026, и каждый требует **второго
клиента** (Telegram Desktop или телефон) — проверить их изнутри одного lazytg
нельзя.

🔴 **Чат должен быть открыт ДО отправки.** Прошлый прогон дважды прочитали как
баг «сообщение не приходит в тред», хотя тред был закрыт: закрытый тред
сообщение и не рисует, оно попадает в зеркало и появляется при открытии. Живой
путь проверяется только так: сначала открыть чат в lazytg, потом писать.

- [ ] Отметка о прочтении: открыть в lazytg чат с непрочитанными — бейдж в
      Telegram Desktop гаснет; повторный вход в тот же чат нового запроса
      не порождает (в логе нет второй строки `read:`)
- [ ] Удалённое сообщение: удалить сообщение со второго клиента при открытом
      чате — строка уходит из треда, а `lazytg search` его больше не находит
- [ ] Удалённый чат: удалить чат целиком со второго клиента — после
      ближайшего синка диалогов он исчезает из списка вместе с историей
- [ ] Новый чат: попросить написать контакт, которого нет в списке — строка
      появляется как `chat <id>` и в течение нескольких секунд получает имя
      **без перезапуска**

### 12b. Подписи, счётчик и курсор

Три дефекта второго живого прогона (19.08.2026). Все три видны только на
живом аккаунте: в тестах отправитель приватного сообщения задан явно, а
Telegram его как раз не присылает.

- [ ] Автор: в личном чате входящие подписаны именем собеседника, свои — `you`.
      🔴 Проверять **после переоткрытия чата**: подпись раньше терялась именно
      при повторном заходе, когда `messages.getHistory` перезаписывал строку.
      Сообщения, сохранённые до этой сборки, остаются `system`, пока чат не
      откроют заново
- [ ] Счётчик: написать в чат, который в lazytg **не открыт**, — рядом с ним
      появляется `(1)` без перезапуска и без синка диалогов
- [ ] Открытый чат бейджа не получает: писать в чат, открытый в lazytg, —
      счётчик остаётся пустым, а бейдж на телефоне гаснет по мере чтения
- [ ] Курсор: поставить курсор на второй чат в списке и попросить написать в
      третий — курсор остаётся на выбранном чате, хотя список пересортировался

### 13. Polling fallback

Запустить `lazytg --polling` и убедиться по логу, что fallback поднялся
(`tui: history polling engaged`), а сообщения не дублируются в треде: polling
работает вместе с push-обновлениями и обязан пропускать всё, что live-путь уже
сохранил.

🔴 **Логи смотреть в файле, а не через `--debug`.** Флаг дублирует их в stderr,
а TUI рисует в alt-screen — строки лога лягут поверх интерфейса и разнесут
картинку ровно тогда, когда за ней надо следить. Вторым терминалом:
`tail -f "$HOME/Library/Application Support/lazytg/lazytg.log"` (на Linux —
`$XDG_STATE_HOME/lazytg/lazytg.log`).

- [ ] В логе есть `tui: history polling engaged`
- [ ] Входящее сообщение появляется в треде ровно один раз
- [ ] Без флага строки `history polling engaged` в логе нет

### 14. Reconnect

🔴 **Гасить надо тот интерфейс, по которому реально идёт трафик, и все запасные.**
Первый прогон 19.08.2026 едва не прошёл впустую: чек-лист предлагал
`networksetup -setairportpower en1 off`, а дефолтный маршрут на машине шёл
через Ethernet `en0` — Wi-Fi можно было выключать сколько угодно, соединение
этого не заметило бы, и статус-бар остался бы зелёным. Проверить перед
началом: `route get default | grep interface`, и посмотреть, нет ли второго
живого линка (`ifconfig <dev> | grep "inet "`). Оба вниз:
`networksetup -setairportpower en1 off` плюс вынуть кабель или
`sudo ifconfig en0 down`.

- [ ] Запустите TUI, дождитесь `online` в status-bar
- [ ] Отключите интернет на 30 секунд
- [ ] Status-bar переключается на `offline` (красный)
- [ ] Включите интернет обратно
- [ ] Status-bar переходит через `connecting` (жёлтый) → `online` (зелёный)
- [ ] Сообщения, пришедшие во время disconnect, доезжают через difference recovery
- [ ] Они доезжают **в правильном порядке** — live-путь и polling публикуют
      одновременно, и порядок доставки не обязан совпадать с хронологией
- [ ] В логе есть строки `reconnect: transport state` с обеими сменами
      состояния. Их отсутствие означает, что обрыва клиент не заметил, —
      это отдельный дефект, а не «всё хорошо»
- [ ] Напишите с другого аккаунта в чат, **которого ещё нет** в списке: чат
      должен появиться сам, а сообщение — сохраниться. До 19.08.2026 оно
      терялось на внешнем ключе, а чат не возникал до перезапуска

### 15. Read-only degradation

- [ ] Закройте TUI
- [ ] `chmod 0444 ~/Library/Application\ Support/lazytg/lazytg.db` (macOS) или эквивалент на Linux
- [ ] Запустите TUI заново
- [ ] Status-bar показывает `read-only` в storage-cell
- [ ] Чтение работает (чаты + история отображаются)
- [ ] Попытка отправить сообщение → ошибка graceful (не паника)
- [ ] `chmod 0600` обратно — после ≤30 секунд status flip на `rw` без перезапуска

### 16. Quit

- [ ] `Ctrl+C` или `Ctrl+Q` — TUI завершается чисто
- [ ] Терминал восстанавливается (alt-screen exit)
- [ ] `goroutine leak` отсутствует (можно проверить через `lsof | grep lazytg` после `kill`)

## Stage 3 — Search, Files, Палитра, Безопасность

### 17. Search overlay

- [ ] `/` (когда фокус не в Input/Chats-filter) — открывается search overlay поверх 2-pane
- [ ] Печатаете `привет` → через ≤200ms появляются результаты с подсветкой совпадений
- [ ] `↑/↓` — переключают cursor по результатам
- [ ] `Enter` на результате → переход в нужный чат + viewport позиционирован на сообщение с контекстом ±5
- [ ] `Esc` — overlay закрывается, фокус восстанавливается на исходный pane
- [ ] Operators работают:
  - [ ] `from:@username` — только сообщения от пользователя
  - [ ] `in:#chat` — только в указанном чате
  - [ ] `before:2026-01-01` / `after:2025-12-01` — фильтр по дате
  - [ ] `has:file` — только сообщения с media
  - [ ] `"точная фраза"` — phrase search
  - [ ] `-слово` — exclusion

### 18. Командная палитра L1

- [ ] `Ctrl+Space` (или `Ctrl+@`) — открывается палитра по центру экрана
- [ ] Пустой query → top-50 чатов в порядке frecency (свежие × частые)
- [ ] Печатаете `Алёна` → находит чат "Алена" (Unicode normalize: ё → е)
- [ ] `↑/↓` + `Enter` — переход в чат
- [ ] `Esc` — закрытие
- [ ] После выбора чата frecency обновляется (закрыть-открыть палитру → выбранный чат поднялся вверх)

### 19. Files: download (Ctrl-D)

- [ ] Откройте чат с сообщением, содержащим фото или документ
- [ ] Status-bar в Thread показывает badge типа `[📎 report.pdf, 229.1 KiB] ctrl+d to save`
- [ ] `Ctrl+D` — в status-bar появляется ⬇ chip с прогрессом
- [ ] По завершении файл лежит в `~/Downloads/lazytg/<chat-title>/<filename>` (sanitized: слеши заменены на `_`)
- [ ] Permissions файла = `0600`
- [ ] Повторный `Ctrl+D` на том же сообщении → instant complete (dedup hit)
- [ ] Удалите файл, повторный `Ctrl+D` → перезакачка (stale dedup honoured)

### 19a. Курсор по сообщениям и просмотр вложения

Закрывает то, чего до 04.09.2026 в клиенте не было вовсе: выбрать **не последнее** вложение и посмотреть его.

- [ ] Фокус в Thread. `↑` — маркер `▸` появляется у последнего сообщения, следующие `↑`/`↓` двигают его по одному сообщению
- [ ] Маркер видно ровно у одного сообщения; при уходе курсора за край окна тред докручивается **на минимум**, а не перецентровывается
- [ ] Клик по сообщению ставит маркер туда же, куда его поставили бы стрелки
- [ ] Приходит новое сообщение, пока курсор стоит выше → курсор **остаётся на своём сообщении**, не сползает
- [ ] Переключение на другой чат и обратно → курсор снова на последнем сообщении
- [ ] В чате с **двумя** вложениями: поставить курсор на верхнее, `Ctrl+D` → скачивается **верхнее**, не последнее
- [ ] `Ctrl+R` из Input цитирует сообщение под курсором, а не последнее
- [ ] `o` на вложении → файл открывается системным просмотрщиком; повторное `o` открывает мгновенно (без сети)
- [ ] Клик **по строке бейджа** открывает вложение; клик по любой другой строке того же сообщения только двигает курсор
- [ ] `o` при фокусе в Input **печатает букву `o`** в поле ввода, а не открывает файл
- [ ] `LAZYTG_OPEN_CMD="mpv --loop" lazytg` → кружочек проигрывается в mpv по кругу

### 19b. Виды вложений и коллизии имён

- [ ] Кружочек рисуется как `[⏺ video note, 0:07, 1.2 MiB]`, голосовое — `[🎤 voice, 0:42, …]`, обычное видео — `[🎬 <имя файла>, …]`
- [ ] Сообщения, сохранённые **до** обновления, тоже становятся кружочками при первом открытии чата: миграция строки не переписывает, но обычный backfill перекачивает историю и прогоняет её через новый конвертер. Проверено живьём 04.09.2026
- [ ] Два разных видео, оба присланных как `video.mp4`, скачиваются в **разные** файлы: `video.mp4` и `video (2).mp4`. 🔴 Кружочки для этой проверки годятся: Telegram присылает у них атрибут имени `video.mp4`, и генерируемое `video_note_<id>.mp4` включается только когда атрибута нет. Живой прогон 04.09.2026 дал семь файлов `video.mp4` … `video (7).mp4` разного размера — до фикса остался бы один
- [ ] Открыть первое из них после скачивания второго → показывается **первое** видео, а не второе

### 19c. Разделители дат

- [ ] В треде с историей за несколько дней между днями стоит строка `─── August 19 ───`
- [ ] Сегодняшний день подписан `Today`, вчерашний — `Yesterday`, прошлогодний — с годом (`December 31, 2025`)
- [ ] Внутри одного дня разделитель ровно один, а не перед каждым сообщением
- [ ] Клик по строке разделителя не выделяет соседнее сообщение и ничего не копирует

### 19d. Текст от постороннего не управляет терминалом

Проверять со **второго** аккаунта: отправитель должен быть не вы, иначе часть путей рендера не задействуется. Достаточно одного сообщения и одного файла.

- [ ] Отправьте сообщение, в тексте которого есть ESC-последовательность (в bash: `printf 'before\033]52;c;aGVsbG8=\007after'`). В треде видно `before]52;c;aGVsbG8=after` одной строкой — буфер обмена **не** изменился (проверить `pbpaste` до и после открытия чата)
- [ ] Переименуйте файл так, чтобы имя содержало `\033[2J`, и отправьте. Бейдж рисует имя как текст, тред не перерисовывается, соседние сообщения на месте
- [ ] Назовите чат (или контакт) с ESC-последовательностью в имени → список чатов рисует её как текст, строки не съезжают
- [ ] Найдите такое сообщение через `/` → сниппет в оверлее тоже чистый

🔴 Проверка именно живая: тесты фиксируют поведение функции, а сходится ли это с тем, что реально делает ваш терминал, покажет только он. Ghostty и iTerm2 исполняют OSC 52 по-разному в зависимости от настроек.

### 19e. Действия над сообщениями (ветка `feat/message-actions`)

Порядок пунктов — по убыванию риска, а не по удобству: первые два трогают чужие сообщения и чужие чаты.

- [ ] **Черновик остаётся в своём чате.** Напишите половину фразы в чате A → переключитесь в B → вернитесь в A. Текст на месте, в B пусто. Если был армирован reply — он вернулся вместе с текстом
- [ ] `Space` отмечает сообщение под курсором, отметки копятся; `y` копирует отмеченные (проверить `pbpaste`), `Esc`/смена чата отметки снимает
- [ ] `e` на **своём** сообщении открывает его текст в композере, Enter сохраняет, `Esc` возвращает вытесненный черновик. `e` на чужом — отказ **сразу**, без запроса к серверу
- [ ] `d` спрашивает и предлагает «у всех / у себя» в личке и группе; **в канале выбора нет** — там удаление всегда для всех
- [ ] 🔴 **Удаление в канале удаляет именно то сообщение.** Канал нумерует сообщения с единицы: проверить, что удалилось выбранное, а не сообщение с тем же номером в другом чате
- [ ] `f` открывает палитру выбора чата и **ничего не отправляет** до выбора; `Esc` отменяет, отметки остаются. Пересылка из канала в личку доходит; выбор чата-источника отклоняется с объяснением

### 19f. Реакции, typing, непрочитанное

- [ ] `r` открывает эмодзи-панель, выбор ставит реакцию; счётчик под сообщением совпадает с тем, что показывает телефон (проверить именно сверкой — счётчик берётся из ответа сервера, не считается локально)
- [ ] Повторный `r` + та же эмодзи снимает реакцию; другая эмодзи заменяет
- [ ] Реакция, поставленная с телефона, появляется здесь без переоткрытия чата
- [ ] Пока собеседник печатает, в статусбаре видно `typing…`; голосовое даёт `recording a voice message…`. Индикатор **сам гаснет** через ~6 секунд после того, как он перестал печатать
- [ ] Откройте чат с непрочитанными (написать себе с телефона 3–5 сообщений): над первым непрочитанным стоит `─── 3 new messages ───`, и линия **не уезжает**, пока читаете. Новые сообщения приходят ниже линии

### 19g. Картинки, звук, навигация

- [ ] 🔴 **`i` на фото рисует его в треде и не размножает.** Ghostty/kitty/WezTerm: нажать `i`, затем прокрутить тред вверх-вниз несколько раз — копий картинки в панели быть не должно. Второе `i` убирает картинку с экрана (а не только из разметки), смена чата тоже
- [ ] Внутри `tmux` `i` отвечает «этот терминал не умеет» и ничего не печатает в панель. `LAZYTG_IMAGE_PROTOCOL=kitty` включает принудительно
- [ ] `i` на видео/кружочке — отказ с подсказкой про `o`, а не пустой экран
- [ ] Голосовое сообщение рисует волну блоками (`▂▄▆█`) рядом с длительностью; пауза в записи видна как провал
- [ ] `p` на ответе переходит к сообщению, на которое отвечают (курсор встаёт на него), `Ctrl+O` возвращает. Цепочка ответов проходится несколькими `p` подряд
- [ ] `p` на сообщении, которое ответом не является → «this message is not a reply», курсор не двигается
- [ ] `[` / `]` листают телеграмные папки; `All` первая, список фильтруется. Папка-чатлист (по ссылке) показывает только явно входящие в неё чаты
- [ ] `Alt+1`…`Alt+9` открывают N-й чат **в текущей папке**; номер больше длины списка → «no chat there», выбор не двигается
- [ ] `Alt+E` открывает эмодзи-панель: набор фильтрует, `[`/`]` листают категории, выбранное попадает в композер, недавние возвращаются первыми
- [ ] В композере `:rocket` + `Tab` → 🚀; повторный `Tab` листает варианты. `Tab` без `:слова` под курсором по-прежнему переключает фокус между панелями. `10:30` + `Tab` двоеточие **не** съедает

### 19h. Форматирование и правки с других устройств

- [ ] В списке чатов есть `Saved Messages`, даже если на аккаунте туда ничего не писали; отправка в него доходит (видно на телефоне в «Избранном»)

- [ ] Отправить с телефона сообщение с **жирным**, `кодом`, ~~зачёркнутым~~ и ссылкой за словом: здесь жирное жирное, код серый, зачёркнутое зачёркнуто, а рядом со словом-ссылкой стоит `⟨host⟩`
- [ ] Спойлер с телефона рисуется серым блоком; курсор на сообщении раскрывает его, уход курсора прячет обратно
- [ ] В композере набрать `**жирно** и \`код\`` → на телефоне сообщение отформатировано, звёздочек нет. Строка `2 * 3` уходит как есть
- [ ] Строка `🚀 **go**` — на телефоне жирное именно `go`, не сдвинуто на символ (эмодзи считаются в UTF-16)
- [ ] `e` на своём форматированном сообщении показывает разметку (`**…**`), Enter сохраняет формат; на телефоне сообщение помечено «edited», здесь в заголовке `edited`
- [ ] Поправить своё сообщение **с телефона**: здесь текст меняется на месте, без прокрутки, появляется `edited`, счётчик непрочитанных не растёт

### 19i. Список чатов и действия над чатом

- [ ] В строке чата справа время последнего сообщения (`12:30` / `Yesterday` / `Mon` / `05.09`), на второй строке справа `(N)` непрочитанных, `🔕` у замьюченного
- [ ] Прочитать чат **на телефоне** — счётчик здесь обнуляется без переоткрытия; замьютить/закрепить на телефоне — здесь появляется `🔕` / `📌`
- [ ] Открыть личный чат: в статусбаре после названия `· online` или `· last seen …`; когда собеседник выходит в сеть — меняется само
- [ ] В списке (фокус на нём): `m` мьютит — на телефоне чат замьючен «навсегда», повторное `m` снимает; `p` закрепляет/открепляет — порядок списка меняется; `u` на чате с непрочитанными помечает прочитанным (телефон согласен), `u` на чистом ставит точку `●`
- [ ] `p` в **треде** по-прежнему переход по ответу, `m`/`u` в композере печатают буквы
- [ ] Открыть чат через палитру (`Ctrl+Space`): подсветка в списке перешла на него, `m` мьютит именно его
- [ ] Написать себе с телефона в чат, который здесь **не открыт**: терминал звонит (Ghostty — иконка в доке), заголовок вкладки `lazytg (1)`; прочитать на телефоне — заголовок снова `lazytg`, `unread 0` в статусбаре. С `LAZYTG_NOTIFY=off` тишина
- [ ] В группе видны служебные строки: «created the group “…”», «pinned a message», пропущенный звонок в личке — «missed call»

🔴 Миграции `0012`–`0016` накатятся на рабочую БД при первом запуске ветки. Бэкап до запуска: `cp ~/Library/Application\ Support/lazytg/lazytg.db ~/Library/Application\ Support/lazytg/lazytg.db.bak-before-0012`. Миграция `0014` добавляет колонки `entities` и `edit_date`, `0015` — `muted_until`, `unread_mark`, `online`, `last_seen` в `chats`, `0016` — `read_outbox_max_id` там же.

### 24. Send rate-limit (manual stress test)

- [ ] Отправьте 30 сообщений подряд через Input pane (зажав Enter с paste-buffer'ом)

- [ ] Последующие сообщения (31+) уходят со скоростью ~10 msg/sec — заметная задержка между каждой отправкой

### 25. lazytg reindex
